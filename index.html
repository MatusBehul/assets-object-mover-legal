Assets Object Mover for Jira

Move Assets objects to another object type or schema. Values come along, and every object and Jira issue that pointed at them is updated.

Getting started

Install the app from the Atlassian Marketplace on a Jira site with Jira Service Management and Assets. There is nothing to set up. Open Jira settings → Apps → Assets Object Mover.

The app works as you, with your own Assets permissions. To move objects you need to be able to edit objects in both schemas, and to update linked Jira issues you need to be able to edit those issues.

Move objects

  1. Objects to move. Choose the schema and object type. To move only some of them, type an AQL filter, such as Status = "Retired". The page shows how many objects match.
  2. Where they go. Choose the target schema and object type, and whether to move or copy.
  3. Match the attributes. Attributes with the same name are matched for you. Change any match, or type a value that every moved object gets. Required attributes must have a match or a value. Attributes that cannot hold each other's values, such as text and a date, can't be matched; anything can go into a text attribute as plain text.
  4. Run. Click Move 1 object to try first, check the result, then move the rest.

Keep the page open while it runs. If you close it, the run pauses and carries on when you open the page again. When it finishes, Download the log gives a CSV of every old key and its new key.

What a move does

For each object, the app:

  1. creates a new object in the target type with the matched values;
  2. points every object that referenced the original at the new one;
  3. updates every Jira issue whose Assets field held the original;
  4. deletes the original.

A copy does only the first step and leaves the originals and their links alone. In both, links between objects moved in the same run follow the new objects.

The app never deletes an original that something still needs. If another object's reference attribute only accepts the old object type, or an update fails, the original is kept and the log says why. Check it and delete it by hand.

Questions

Do object keys stay the same?

No. In Assets a key belongs to its object type and schema, so the new object gets a new key. The log lists both.

What doesn't move?

Comments, history, attachments and avatars stay with the original object, because Assets has no way to move them. The values of attributes you don't match aren't copied; the page lists them before you start.

Are watchers emailed when a Jira issue is updated?

The app asks Jira not to send notifications for these updates. If you're not allowed to turn notifications off, the update is made as a normal edit.

Can I undo a move?

Move the objects back with the app. Try one object first to check the attribute matches.

Does the app send my data anywhere?

No. It runs on Atlassian's Forge platform and has no servers of its own. See the privacy policy.
